# Журнал изменений DeskDancer

## v2.5.0
- Общие модули: safe_json 1.1.1 — config.json пишется атомарно, с .bak; испорченный не затирается (берётся
  config.json.bak, копия испорченного — config.json.bad-<время>; нет копии — настройки по умолчанию, файл не
  перезаписывается); app_log 1.2.1 — журнал deskdancer.log (там же, то же имя): пароли и токены скрыты и в файле, и
  в окне «Журнал», падения — в deskdancer_crash.log; для разработки — bump_version.py / release.py / check_leaks.py
  1.1.0 (release.json).
- `--selftest` — пункты «надёжная запись настроек (safe_json)», «журнал программы (app_log)», «версия во всех местах
  (release.json)»; сборка EXE — шаг «Проверка утечек», модули safe_json и app_log.

## v2.4.0
- Значок программы: окно выбора (общий модуль app_icon 1.2.0) — меню ⋯ → «🎨 Значок программы…»; встроенная
  база ~370 значков (без интернета, поиск по-русски), поиск в интернете, своя картинка (файл, Ctrl+V,
  перетаскивание, значок сайта); `deskdancer.ico` рядом с программой и значок ярлыкам.
- «По умолчанию» возвращает родной значок; пока значок не выбирали — всё как раньше, файлы не пишутся.
  Выбранный значок ставится при запуске окнам и полосе заголовка.
- `--selftest` — пункт «значок программы (app_icon)»; сборка EXE — модули и база значков.

## v2.3.1
- Обновление с GitHub — общий модуль gh_update 1.5.3: неполный архив не ставится (раньше мог стереть по списку
  почти всю программу); копия из git не обновляется (в ней — git pull); «можно ли ставить» проверяется ещё раз
  после скачивания; скачивание при выходе из программы бросается; кривой токен не попадает в журнал; свои папки
  tools/ и modules/ не чистятся и по списку файлов.

## v2.3.0
- Видеокарта: деформация девушек по костям — в вершинном шейдере (процессор больше не пересчитывает вершины),
  неон — шейдерами в 6 проходов (контур, два размытия, сборка), кадр читается с видеокарты по запросу.
- До 60 кадров/с с видеокартой (было 16 на GTX 1070 в неоне). Программная графика — как прежде, 30.
- Шейдер не рисует на этой видеокарте — движок сам возвращает кости / неон процессору (запись в журнале).
- Видеокарта без sRGB-буфера больше не мешает включить режим «видеокарта».

## v2.2.0
- Всё ставится только рядом с программой: библиотеки — в `libs/` (pip `--target`, без кэша), Python для 3D —
  в `.runtime/`. В системный Python ничего не ставится (нет `--user`, `ensurepip`), чужие Python не используются.

## v2.1.0
- Python 3.15: для него нет сборок Panda3D — программа больше не останавливается с «Не удалось установить
  panda3d». 3D-движок запускается в отдельном Python: уже установленный 3.10–3.14 (py-лаунчер) или компактный
  Python 3.13 с python.org в `.runtime/` (ставится сам, один раз). Кадры передаются в окно программы.
- panda3d — не обязательная библиотека: на Python до 3.14 ставится сама, как раньше.

## v2.0.0 — без браузера
- 3D-сцена больше не в браузере (QtWebEngine + three.js): её считает **Panda3D** прямо в Python, в своём потоке,
  а готовый кадр с прозрачностью рисуется в окне Qt (QPainter) — как скины PionerFM.
- Графика: «Авто» (видеокарта OpenGL → DirectX 9 → процессор), «Видеокарта», «Процессор». Программная графика
  работает на любом ПК, даже где WebGL / видеокарта недоступны (~30 кадров/с, 3 девушки).
- Свой загрузчик GLB/GLTF (сетка, текстуры, скиннинг на numpy) и перенос танцев на Python — те же правила, что в 1.x.
- Неон — на процессоре (numpy): контур, ореол, палитры, вспышка на долю.
- Встроенного манекена нет (старые сцены → девушки из комплекта). FBX пока не читается — перевести в GLB (Blender).
- Предпросмотр на странице «Сцена» и окно сцены показывают одну и ту же сцену; никто не смотрит — сцена на паузе.

## v1.5.0
- Режим графики «Авто / OpenGL / Программный» («Окно»); по умолчанию WebGL включён и на видеокартах
  из «чёрного списка» Chromium.
- Проверка предпросмотра: нет WebGL, нет кадров или девушки на экране не двигаются — программа предлагает
  перезапуск в следующем режиме.
- В журнал — видеокарта сцены, ошибки страницы, «страница сцены не загрузилась».

## v1.4.0
- «Предпросмотр» на странице «Сцена»: девушки танцуют прямо в окне программы.
- Прозрачная сцена на Windows: альфа-буфер QtWebEngine; проверка через 8 с — если девушки на экране
  не видны (два снимка экрана не различаются), сцена сама переходит на тёмный фон.
- «Окно» → «Фон сцены»: прозрачный / тёмный; «🎯 Найти сцену»; первый показ — рядом с окном программы.
- В журнал — кадры/с сцены, сколько девушек загрузилось, где окно.

## v1.3.0
- Режим «✨ Неон»: светящийся контур фигуры и складок (Собель по цвету и силуэту) с широким свечением,
  палитры «Огонь», «Неон», «Радуга», вспышка на каждую долю. «Сцена» → «Вид», сила свечения 0–200 %.

## v1.2.0
- Ещё 5 танцев в комплекте из Microsoft Rocketbox (MIT): Драйв, Стильный, Ровный, Озорной, Страстный — всего 10.

## v1.1.0
- В комплекте 10 реалистичных девушек и 5 женских танцев из Microsoft Rocketbox (MIT), сконвертированы в GLB.
- Сцена по умолчанию — три девушки из комплекта.
- Скелет 3ds Max Biped: имена костей, перемещение тела через Bip01; танцы Mixamo подходят к девушкам Rocketbox
  и наоборот (поправка разной позы покоя T / A).
- Папки `_other/` в библиотеке не читаются.

## v1.0.0
- Первая версия: прозрачная 3D-сцена на рабочем столе (three.js в QtWebEngine), до 6 девушек.
- Такт из звука ПК (WASAPI loopback), микрофона или вручную (BPM, «тап»); темп и фаза танца — под музыку.
- Модели GLB/GLTF/FBX, танцы из отдельных файлов; перенос анимации через мировые повороты костей
  (Mixamo FBX ↔ GLB из Blender), имена костей CC4 / Unreal / Daz / VRM → Mixamo.
- Реалистичный свет (PBR-окружение, ACES), встроенный манекен с 4 танцами, пресеты сцен.
- Окно в стиле программ: своя рамка, тема ☀/☾, меню ⋯, правый клик везде, автосохранение, обновление с GitHub.
